# Layout and delivery

Use these defaults for an ordinary industry application when the user has not specified a layout. Employer instructions, the requested artifact, and regional conventions take precedence. A visual portfolio handout can justify other choices; retain a clear reading order and do not silently replace the user's chosen design.

## Information hierarchy

- Put the candidate's name and text-based contact information at the top of the document body. Add relevant portfolio or professional links. Use a city or region when useful; a full street address is usually unnecessary.
- Use conventional headings such as Experience, Projects, Skills, and Education, localized naturally for the resume language. Distinguish employer, title, project, and date through consistent hierarchy.
- Give the strongest role-relevant evidence the most space. Keep the first page useful on its own. Do not create a crowded first page and a nearly empty second page just to preserve every source bullet.
- Use reverse chronology within dated sections. Keep dates, punctuation, capitalization, indentation, and bullet structure consistent. Do not change an official title to imitate a job posting.
- Make links identifiable through readable text. Icons, skill bars, logos, and color alone should not carry essential information.

## Visual defaults

| Element | Practical starting point | Adjust when |
| --- | --- | --- |
| Columns | One flowing text column | A requested portfolio or handout has a demonstrable need for another layout. |
| Body type | Approximately 10.5-12 pt; choose a font with suitable language coverage | Font metrics or script require a different size for comfortable reading. |
| Name and headings | A visibly stronger name; modest, consistent section emphasis | The existing document already has a readable hierarchy. |
| Margins | Approximately 0.5-1 inch, usually nearer 0.75 inch | A submission template or regional page format specifies them. |
| Color | High-contrast text with restrained accents | The audience and requested visual design justify additional color. |
| Bullets | Usually one or two rendered lines per accomplishment | A meaningful contribution genuinely needs more context. |
| Length | Often one page for early career; one or two for substantial relevant experience | The employer or document type requires a different length. |
| Page size | A4 or US Letter according to destination and existing format | The employer specifies a template. |

These are layout starting points, not hiring requirements or automatic rejection thresholds. The one-page convention does not justify tiny type, compressed character spacing, or removal of essential evidence. Improve selection and wording before reducing readability. Avoid broad blocks of bold text; emphasize section structure and a few high-value signals.

Default to omitting photos, age, marital status, salary expectations, generic self-evaluations, references-on-request lines, and closing thank-you sentences unless the application context asks for them. Avoid importing one country's conventions into every market.

## File format and parsing

Follow the destination's accepted formats. A text-based PDF preserves presentation when accepted; DOCX is appropriate when requested or supported. Editable source is useful when requested, but a content-only edit does not need both formats. HTML or Markdown can be a working format; do not assume an application portal accepts them.

For a document intended for routine parsing, use ordinary paragraphs and genuine list structure. Prefer essential information in the body over document headers, footers, floating text boxes, or layout tables. Keep technologies in normal text, including a job posting's equivalent terminology where supported. Do not add invisible keywords, duplicate keyword blocks, or invented skills.

Parsing, recruiter search, job matching, and a human screening decision are different processes. Readable structure can reduce extraction problems; it cannot guarantee selection or establish a universal ATS score. A summary is not mandatory for keyword visibility, and no evidence here establishes a special ATS advantage for four to six bullets.

## Check the actual deliverable

When producing or changing a formatted document:

1. Open or render the final exported artifact using available tools. Inspect every page for clipping, overflow, unexpected blank space, font substitution, crowded text, and page breaks that separate a heading from its first content.
2. Extract text or copy it into plain text. Inspect section order, names, dates, contact details, bullets, technical names, punctuation, and multilingual characters. An extraction success is a local check; application systems can still behave differently.
3. Verify visible URLs and link targets. Keep link text meaningful when printed. Check the actual destination's file constraints when available, without generalizing one provider's limits to every ATS.
4. Reconcile final text with the agreed facts and latest answers. Remove unresolved placeholders from an application-ready document.

If the environment cannot render or extract the requested format, inspect what is available and state the remaining check briefly. Do not describe an unrendered document as visually verified or an unsubmitted resume as tested in the employer's ATS. For a plain-text rewrite, limit claims to content review.
