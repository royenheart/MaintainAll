# Layout and delivery

Use these defaults for an ordinary industry application when the user has not specified a layout. Employer instructions, the requested artifact, and regional conventions take precedence. A visual portfolio handout can justify other choices; retain a clear reading order and do not silently replace the user's chosen design.

## Information hierarchy

- Put the candidate's name and text-based contact information at the top of the document body. Add relevant portfolio or professional links. Use a city or region when useful; a full street address is usually unnecessary.
- Use conventional headings such as Experience, Projects, Skills, and Education, localized naturally for the resume language. Distinguish employer, title, project, and date through consistent hierarchy.
- Give the strongest role-relevant evidence the most space. Keep the first page useful on its own. Do not create a crowded first page and a nearly empty second page just to preserve every source bullet.
- Use reverse chronology within dated sections. Keep dates, punctuation, capitalization, indentation, and bullet structure consistent. Do not change an official title to imitate a job posting.
- Make links identifiable through readable text. Icons, skill bars, logos, and color alone should not carry essential information.

## Visual defaults

| Element | Practical starting point | Adjust when |
| --- | --- | --- |
| Columns | One flowing text column | A requested portfolio or handout has a demonstrable need for another layout. |
| Body type | Approximately 10.5-12 pt; choose a font with suitable language coverage | Font metrics or script require a different size for comfortable reading. |
| Name and headings | A visibly stronger name; modest, consistent section emphasis | The existing document already has a readable hierarchy. |
| Margins | Approximately 0.5-1 inch, usually nearer 0.75 inch | A submission template or regional page format specifies them. |
| Color | High-contrast text with restrained accents | The audience and requested visual design justify additional color. |
| Bullets | Usually one or two rendered lines per accomplishment | A meaningful contribution genuinely needs more context. |
| Length | Often one page for early career; one or two for substantial relevant experience | The employer or document type requires a different length. |
| Page size | A4 or US Letter according to destination and existing format | The employer specifies a template. |

These are layout starting points, not hiring requirements or automatic rejection thresholds. The one-page convention does not justify tiny type, compressed character spacing, or removal of essential evidence. Improve selection and wording before reducing readability. Avoid broad blocks of bold text; emphasize section structure and a few high-value signals.

Default to omitting photos, age, marital status, salary expectations, generic self-evaluations, references-on-request lines, and closing thank-you sentences unless the user or application context asks for them. An explicitly required photo stays in the design. Avoid importing one country's conventions into every market.

## Compose the header and interactive details

Treat the photo, name, professional focus, and contact details as a single composition. When a photo is requested, place it in a defined relationship to the identity block using alignment, spacing, scale, or a shared background. Check the whole header at actual size: a photo stranded at one margin while all text is independently centered can look detached. A grouped photo-left, identity-right header is one option, not a universal template. Preserve the supplied image's proportions and likeness; layout work does not authorize retouching or generating a replacement portrait.

Use real hyperlinks for the supplied website, portfolio, GitHub, email, or other relevant destinations. Preserve visible domain names or meaningful addresses that remain useful in print and extract as text. Confirm uncertain destinations from the user's material or an authorized source rather than guessing a personal URL. Link appearance can combine accent color with a fine underline or another restrained cue. Check contrast, underline position, wrapping, and whether adjacent contacts remain visually distinct.

Icons may supplement text labels but should not replace essential contact information. Prefer small vector shapes or glyphs whose export has been checked; private-use icon characters can pollute extracted text. Keep keywords, dates, email addresses, and links as ordinary selectable text. Use weight, color, or a short highlight to emphasize a few meaningful results or mechanisms, without bolding most of each paragraph. Check grayscale readability and the interaction between link underlines, rules, and highlighted numbers.

## Explore and refine a requested visual direction

For an explicit design exploration, use available visual-design skills when appropriate. Inspect supplied references and research primary examples when research is requested. Identify the transferable choices: hierarchy, photo grouping, typography, spacing, palette, and link treatment. Adapt them to a resume's density and reading order; a reference website or poster is not automatically a suitable document template. Do not impose this research workflow on a wording-only request.

Make alternatives meaningfully different in composition or type, rather than changing only accent colors. Keep the same reviewed content across variants so the user can compare their design. Use the requested number of alternatives, or a small useful set when unspecified. Render actual editable documents and label their previews clearly; a screenshot mockup alone does not establish a working resume. Save enough style parameters or source to reproduce the result without requiring a particular renderer.

Choose fonts by rendered evidence. Compare relevant candidates using the actual language, technical terms, numerals, punctuation, links, and mixed-script text at the intended body size and leading. Check actual weight availability, language coverage, visual balance between scripts, line lengths, and document density. Export and inspect the selected fonts: substitution, missing glyphs, incorrect Unicode mapping, or variable-font export failures can invalidate a visually plausible choice. Prefer a verified alternative when the available toolchain cannot export a candidate reliably. A font list without real typesetting is insufficient when the user explicitly requests careful font exploration.

Once the user selects a direction, retain its accepted typography, palette, body layout, and content unless later instructions change them. A request to use another variant's header should transfer that grouping and alignment while preserving the selected style's other choices. Re-render the changed region and all affected pages. Keep a recoverable source or prior preview, distinguish the selected direction from unreviewed details of the latest rendering, and update the main editable entry, default export, and comparison labels to the current version. Do not repeatedly reopen settled choices or describe unreviewed changes as user-approved.

## File format and parsing

Follow the destination's accepted formats. A text-based PDF preserves presentation when accepted; DOCX is appropriate when requested or supported. Editable source is useful when requested, but a content-only edit does not need both formats. HTML or Markdown can be a working format; do not assume an application portal accepts them.

For a document intended for routine parsing, use ordinary paragraphs and genuine list structure. Prefer essential information in the body over document headers, footers, floating text boxes, or layout tables. Keep technologies in normal text, including a job posting's equivalent terminology where supported. Do not add invisible keywords, duplicate keyword blocks, or invented skills.

Parsing, recruiter search, job matching, and a human screening decision are different processes. Readable structure can reduce extraction problems; it cannot guarantee selection or establish a universal ATS score. A summary is not mandatory for keyword visibility, and no evidence here establishes a special ATS advantage for four to six bullets.

## Check the actual deliverable

When producing or changing a formatted document:

1. Open or render the final exported artifact using available tools. Inspect every page for clipping, overflow, unexpected blank space, font substitution, crowded text, and page breaks that separate a heading from its first content. Inspect the header, photo grouping, link underlines, and selective emphasis at a useful scale too.
2. Extract text or copy it into plain text. Inspect both natural reading order and layout-aware text where available: sections, names, dates, contacts, technical names, and each numerical claim. Check multilingual characters, arrows, hyphens, ranges, percent signs, and units. Confirm font embedding and Unicode mappings where the format exposes them. Fix observed extraction failures in the source and export; an extraction success is a local check, and application systems can still behave differently.
3. Verify visible URLs and actual hyperlink targets in the export, including email and telephone links when present. Ensure icons do not add replacement or private-use characters to the text. Check the actual destination's file constraints when available, without generalizing one provider's limits to every ATS.
4. Reconcile the final text and export with the source-to-draft map and latest answers, entry by entry. Confirm that merges and shortening preserve the selected mechanisms, numbers, comparison conditions, and ownership. Remove unresolved placeholders from an application-ready document.
5. Confirm that the main editable entry, exported artifact, and previews reflect the current selected variant. When multiple variants are delivered for comparison, verify shared factual content rather than assuming visual differences are the only changes. Deliver the requested source and export with a usable preview when appropriate.

If the environment cannot render or extract the requested format, inspect what is available and state the remaining check briefly. Do not describe an unrendered document as visually verified or an unsubmitted resume as tested in the employer's ATS. For a plain-text rewrite, limit claims to content review.
