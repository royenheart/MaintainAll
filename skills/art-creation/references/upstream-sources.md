## Runtime and packaging boundaries

- Copy the entire `art-creation/` directory, including `methods/`, references, templates, scripts, licenses, notices, and source lock. Relative links resolve from their containing file, not from the shell working directory.
- Only the root skill needs discovery. Nested `SKILL.md` files are ordinary linked resources loaded by the iterative method index; loading all seven at startup defeats progressive disclosure. Host-specific discovery behavior may differ; this hierarchy does not assume automatic recursive skill registration.
- The shared [method contract](method-contract.md) connects each method to the [iterative workflow](iterative-creation.md). Read it once per active workflow. Method switches preserve confirmed constraints and record changed fidelity.
- The procedural viewer loads p5.js 1.7.0 from a CDN. The browser-3D example loads Three.js 0.180.0; its `three` URL parameter can select a compatible local module. A local Three.js module also needs its matching imported dependencies. Templates report failed runtime loading; they are not advertised as offline packages.
- Motion and comparison templates need a modern browser but no framework. The mesh generator needs Python 3. SVG raster export needs an available renderer. The video starter needs a compatible React/Remotion project; it is not a complete video app. No renderer packages or global skills are installed here.
- Library pins identify the supplied examples, not a claim that they are the latest or a recommendation to replace dependencies in an existing project.
- These resources enable explicit construction and feedback. They do not demonstrate general intelligence, infer the user's intent without feedback, or establish that language/programs can replace all visual or motion perception.
