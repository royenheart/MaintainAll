# Art Creation

Turn references and rough ideas into observable design decisions, visible alternatives, and an executable creative brief. The user does not need specialist vocabulary.

## Capability index

| User need | Capability | Read |
|---|---|---|
| Understand a supplied image, webpage, or design; learn how to describe its style | Style analysis with direct annotation and a two-chapter teaching report | [Style analysis](references/style-analysis.md) |
| Start with a vague idea, sketch, or reference and discover the desired result through feedback | Progressive creative exploration with contrasting previews and controlled refinement | [Iterative creation](references/iterative-creation.md) |
| Develop a game idea through sketches, playable experiments, and player feedback | Native engine creation with atomic game decisions | [Game creation](references/game-creation.md) |
| Plan a README demo or product motion artifact | Evidence-vs-narrative workflow, artifact specs, and progressive product-demo decisions | [Product demo workflows](references/product-demo-workflows.md) |
| Borrow one-take motion logic for a launch or concept film | Carry, rhythm, camera, UI rebuild, and continuity verification | [Onetake method](references/onetake-method.md) |

Select the relevant capability. When reference analysis and exploration are both requested, use analysis to inform exploration. Use the two-chapter format for a full analysis report and compact comparisons for exploration rounds.

## Establish the feedback path

After identifying the current intent and next decision, establish a usable feedback path before substantial construction: the user can see, hear, or play the result and respond to the relevant version. Follow [Feedback setup](references/feedback-setup.md) to choose the representation, reuse or prepare the required runtime, and verify a small end-to-end result. Expand the setup as the next question requires.

Then continue the creative loop: [decompose the next intent](references/intent-and-evidence.md), construct meaningful alternatives, collect an atomic response, preserve accepted choices, and refine through [Iterative creation](references/iterative-creation.md). Reuse the prepared feedback path throughout that loop.

## Working approach

- Write reports and creative guidance in accessible Chinese unless the user requests another language. Explain a technical term on first use.
- Turn observations and user preferences into concrete design choices.
- Prefer natural language and inspectable programs: text, source, geometry, pixel statistics, timelines, SVG, HTML/CSS, canvas, procedural models, native game scenes, or frame-based rendering. Use multimodal assistance for perceptual questions these representations leave unresolved.
- Display annotations on the supplied material and render alternatives for comparison.
- Carry the requested medium, content, and accepted choices into each iteration; vary unresolved properties through user feedback.
- Build playable games in their chosen engine from the first prototype; choose native playback, compatible Web export, or remote streaming for feedback.

For concrete inspection, overlay, rendering, and motion methods, read [Programmatic visual methods](references/visual-methods.md) when needed.

Progressive disclosure follows `Art Creation -> relevant capability -> feedback setup -> chosen method -> selected backend/resource`. Follow the branch that answers the current question.
