# Decision: Visual backends and expanded task suite

Status: implemented — explicit offline visual runtimes and versioned relational tasks extend the local benchmark.

## Problem

The framework can declare HTML or native-scene outputs without proving playback or independent reopening. Eight core cases and three trajectory cases leave substantial reference, costume, procedural and spatial requirements untested. Chromium also needs Unix socket syscalls that the pinned Codex restricted-network filter rejects, even for pipe-based debugging.

## Decision

Use standalone trusted [browser](../../../../../../benchmarks/skill_bench/src/skill_bench/browser_driver.py) and [Blender](../../../../../../benchmarks/skill_bench/src/skill_bench/blender_driver.py) evidence drivers, explicit executable identities and fail-closed capability gates. Blender runs under the existing Codex command profile. A narrow [browser broker](../../../../../../benchmarks/skill_bench/src/skill_bench/browser_broker.py) accepts bounded declarative file requests and renders in an independent Bubblewrap namespace with no host network and narrow read-only mounts. Host subscription authentication remains outside both rendering boundaries. The solver cannot choose host commands, runtimes or output paths outside its workspace.

Regrading retains immutable generation telemetry and seals independent raster, trace and edited-native inventories. Pin runtime binaries while recording current trusted verifier/driver identities, so driver improvements can append zero-generation verification without rewriting a run. Restore only references supplied through the current real turn and safely sealed local browser resources. Missing resources or script errors withhold complete reopening. Browser evidence is software 2D sampled playback with explicit time/profile labels; a Blender edit proves one native object transform only. Native bounds and edit selection share active-view-layer render eligibility, including ancestor collection visibility, excluded paths and objects linked into multiple collections. Neither backend creates a quality score.

Review packages freeze an explicit source revision and report import rejects a different revision. Original captures can enter the anonymous quality gallery; verifier-modified captures remain technical evidence. Ratings and paired outcomes carry exact revision provenance, while comparable cohorts use actual method/runtime identities and evidence scope rather than a unique per-run revision ID. The broker publishes completed JSON responses atomically to prevent partial-read failures.

Add the [expanded v3 suite](../../../../../../benchmarks/art_creation/expanded/suite.json): 16 three-turn tasks, 12 development and four holdouts, exact prompt-linked requirements and public asset provenance. Preserve historical core/trajectory bytes and condition fingerprints. Task data, deterministic tests and recorded model evaluations remain distinct populations.

## Alternatives considered

- Static SVG substitutes for browser or native tasks: rejected because they cannot establish playback, responsive state or native scene reopening.
- Enabling unrestricted command networking or rendering on the host: rejected because it breaks the authentication/network boundary.
- Chromium startup flags alone: insufficient; the restricted filter also denies required Unix shutdown operations.
- A general arbitrary-command host broker: rejected in favor of literal capture requests with bounded paths, timing and input actions.
- Rewriting the original suite: rejected because it changes historical task/rubric identities.
- Polygon or component counts as quality metrics: rejected because they measure delivery complexity rather than requested relationships.

## Consequences

Visual execution requires configured free runtimes, a working Linux namespace sandbox and passing runtime doctors. Missing tools reject a plan before generation. Native captures use software Workbench geometry/diffuse views, not shader or rig acceptance; browser sampling and generic keyboard exploration do not prove every interrupted-transition property. New holdouts remain evaluator-side and skill snapshots must be frozen before use. Full multi-arm/repeat coverage needs manually budgeted batches; CI validates datasets and submitted reports without model authentication.

The [verification record](../../../../../../docs/research/skill-benchmark-backends-2026-10-11/verification.json) separates contract checks, actual backend execution and quality review. Two development tasks completed six real turns in the source-pinned Harbor environment. Independent source checks cover 72 sampled browser frames, three native scenes and three saved native transform edits. Original generation seals and the public formal result remain unchanged. Full-suite comparative generation and independent quality review are not claimed.
