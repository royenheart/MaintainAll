# Decision: Small old/new evaluations for each Art Creation change

Status: implemented — The local thin runner and official Codex Linux sandbox pass offline checks and actual isolation probes; records from both model arms stay in private directories outside the repository.

## Problem

A full three-arm matrix and integration with a large evaluation platform delay direct verification of an individual skill change. We need reviewable artifacts quickly, using authorized local authentication and a fixed model, while preventing host skills or AGENTS instructions from contaminating the old arm, exposing credentials, or treating a zero exit code as sufficient acceptance. The existing real trace has no control group and cannot replace this comparison.

## Decision

Use the [small framework](../../../../../../benchmarks/art_creation_ab/README.md): prepare accepts old/new directories or commits, rejects links and unsafe resources, and freezes hashes for the complete skill bundle. Execution starts explicitly. Each change selects 1–2 original tasks with fixed `gpt-6.1-sol` and `low`, identical inputs and permissions, and 2–4 sequential CLI invocations in independent ephemeral sessions. Invocations stop on timeout and are not retried. CLI invocation counts do not represent actual provider request counts.

Reuse the pinned official Codex Linux permission sandbox: deny root access, allow minimal runtime reads and reads from the precise CLI runtime path, allow writes in the current workspace, and make the selected skill read-only. Explicitly deny temporary directories outside the workspace and command network access. The trusted CLI uses the existing authentication directly without copying credentials or changing global configuration. Discovery isolation combines `--ignore-user-config`, `--ignore-rules`, a zero-byte project AGENTS limit, a check that global AGENTS files are absent, per-manifest host skill disabling, plugin disabling, and actual `skills/list` results. Every run first executes doctor probes for host and authentication reads, writes outside the workspace, skill modification, network access, and the skill catalog. A failed probe prevents model execution.

Keep artifact checks separate from aesthetic preference. Scripts only verify the mechanical SVG and brief contract; a person must still inspect visible differences, intent, and capability claims. Raw logs and artifacts stay in private `0700` directories. Currency cost, provider request counts, model snapshot, seed, acceptance, and compaction remain unset when unknown. The first evaluation runs ribbon and fashion-boundary tasks; it does not establish that garment backends, imports, or every skill change have been verified. Details and results are in the [current report](../../../../../../docs/research/art-creation-benchmark-2026-10-09/v0.md). The larger expansion proposal is not a gate for this evaluation.

The separate feedback entry point compares a frozen current baseline with an incremental candidate through two actual user turns. Each task persists a private first conversation and resumes its exact UUID with identical permissions; each round has an immutable artifact snapshot. A synthetic selection confirms only named dimensions and requests one pending revision. Two tasks across two arms use at most eight initial CLI calls. Agent rendering and image-tool returns are recorded per turn from the exact persisted rollout, including code-mode calls. An isolated read-only CairoSVG runtime supplies static rendering, with an additional real sandbox probe. Continuous playback remains unverified under the strict profile. Thread-cumulative CLI token reports are retained and differenced for the second turn before summation. Actual observations are in the [feedback report](../../../../../../docs/research/art-creation-benchmark-2026-10-09/feedback.md).

The independent complex entry point freezes unchanged natural task cards and real reference image bytes, then compares a frozen current baseline with the current skill over up to three genuine rounds. Inputs are copied to a precise read-only workspace subdirectory; the doctor verifies read access and denied overwrite, creation and rename without granting host input directories. CLI attachments and actual persisted user images are distinguished from image-tool returns. Hidden, stage-specific quality atoms stay on the evaluator side. All bounded output files, including prose handoffs, are captured with hashes; workspace ceilings reject excess explicitly. Execution has twelve initial-call and 90-minute wall-clock ceilings and no model retries. Generated programs execute only through the existing sandbox.

Anonymous packets contain previews, references, task feedback, actual handoffs and applicable manual 0/1/2/unverifiable forms. Within-entry hash comparisons never mix arms or tasks. The arm map and raw traces remain separately private. Mechanical delivery success and source self-evaluation leave aesthetic and relational quality unassessed. Hand-off prose may reveal process choices; this is partial anonymization for artifact review, not a user blind trial. Complex snapshots exclude Python caches and record the logical-file hash without changing any prior experiment identity.

## Alternatives considered

- Harbor's existing Codex adapter supports local authentication, but places it inside the task container and bypasses the inner sandbox. An additional adapter is needed to meet the credential boundary; a two-invocation comparison does not justify that integration work.
- NVIDIA/SkillEvaluator Tier 3 reuses Harbor. Its additional provider, MCP, and judge dependencies and setup exceed the current need; retain it as an option when task coverage grows.
- Writing a custom container or only changing cwd would respectively rebuild the security backend or fail to isolate host skills and files. Use the maintained official OS sandbox and test its enforcement directly.
- A full three-arm matrix, 72 or 270 task runs, and paid CI do not meet the current requirement for quick verification of each change within a small budget. Compare frozen old/new snapshots first; expansion requires a specific question and budget.

## Consequences

The framework requires Linux and the pinned npm Codex layout; version changes require revalidation. It only tests behavior after explicit skill loading. Automatic skill triggering and long-term collaboration among multiple people are outside this evaluation's coverage. Individual tasks, a single repetition, and a fixed order provide only local observations; caching and model alias drift affect costs. A timeout limits time, not tokens or monetary cost; subscription calls still consume quota. Untrusted PRs do not execute this framework's model path. Mainline static CI remains separate from private local experiments.

The first evaluation found that the scorer confused harmless XML comments with DOCTYPE or ENTITY declarations. A failing regression reproduced the issue, the scorer was corrected, and both arms were reevaluated with the same version without additional model calls. The original evaluations remain available. This is a framework defect and does not add a case-specific rule to the skill. CairoSVG rendering and view_image inspection of the SVGs are evaluator postprocessing; they do not establish that the agent followed display guidance during the run, measure time to a usable preview, or demonstrate user acceptance.

Feedback records distinguish actual agent rendering and image-tool output from later evaluator inspection. Scorer and telemetry defects are corrected offline for both arms with one final implementation, preserving original records. These include an unrequested playback-status enum, code-mode image calls, and cumulative resume usage. They do not justify rerunning successful model calls or adding case-specific skill rules. Explicit fixture contracts, one repetition, fixed order, and static samples limit any causal or artistic conclusion.

The two reference tasks complete twelve CLI invocations through four exact three-turn conversations. All twelve pass the declared delivery/container checks and return image-tool items; the four initial turns contain eight actual user-image attachments in total. Reference hashes remain unchanged. These observations do not verify independent source reconstruction or assign any quality score. The current arm uses more time and uncached tokens in this sample; the fixed-order single repetition cannot establish a general skill effect.

Offline regressions guard two complex-review defects: preservation comparisons must select one arm and task, and later feedback atoms must only appear on their applicable turns. The corrected exporter produces ninety-four initially blank quality ratings for the full experiment. The separate partial packet retains its own identifiers and review records; immutable PNG hashes can associate the same artifacts across exports without exposing the arm map before assessment.

The [saved complex-task review](../../../../../../benchmarks/art_creation_ab/complex-results.md) freezes all ninety-four ratings before the root agent reads the arm map. It inspects twenty-eight unique PNGs across forty-eight preview slots. This is a root single-agent artifact review with partial anonymization, not independent human preference validation. Frozen v1 receives forty-three 2s, three 1s and one withheld rating; the current snapshot receives forty-two 2s, four 1s and one withheld rating. These tasks do not establish a quality gain or stable version separation. Both costume snapshots retain partial construction/attachment and airy-material expression; the current exhibition has a partial first-round small-corner label-readability judgment.

The first-round exhibition hierarchy atom adds a date/venue priority absent from that turn's prompt. Both ratings are withheld as task/rubric alignment exceptions, rather than treated as model errors; both satisfy the explicitly introduced priority in round 2. Frozen cards, ratings and model outputs remain unchanged. Completed execution is derived from immutable result rows, not the stored manifest state label. Mechanical quality remains unassessed independently of the separate saved review.
