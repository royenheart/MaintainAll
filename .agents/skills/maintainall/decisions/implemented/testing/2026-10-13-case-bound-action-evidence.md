# Decision: Case-bound action evidence and local analysis deliverables

Status: implemented — independent browser observations use frozen turn-specific plans; original-session evidence remains local-private.

## Problem

The [session expansion](../../../../../../benchmarks/art_creation/session-expansion/README.md) contains action, audio and reference-analysis tasks that generic playback stills cannot establish. Solver captions and observation files are claims, and an image-only review omits the requested analysis deliverable. Repeated captures must not become inputs to subsequent captures or inflate their input budget.

## Decision

The [execution plan](../../../../../../docs/superpowers/plans/2026-10-13-action-evidence-and-diverse-screening.md) binds bounded declarative actions, times and controlled audio conditions to the frozen case turn. The trusted offline Chromium driver records actual events, frames and measured signal evidence. Capability promotion requires measured positive and negative acceptance. Source reopening, sampled actions, editability and artistic quality retain separate scopes.

The verifier excludes only its evaluator-owned top-level capture tree from new scenario inputs. The source and trusted tools remain sealed. Browser resource containment is measured separately from filesystem/network confinement. Original-session references, outputs and bounded sanitized analysis text are inspected in explicit local-private reports, which public publication rejects. Historical report bytes and ordinal ratings remain unchanged.

Screenshot serialization must not control the input clock. The pipe transport multiplexes request IDs; an independent bounded scheduler records actual input times and pre-action DOM geometry while capture requests run. Samples wait for actions already due at that sample, failures cancel pending work, and scope shutdown owns all descendants. Case-bound playback scope 3 retains DOM samples, pre-action snapshots and screenshot capture windows. These observations establish sampled state only.

The [failure classifier](../../../../../../benchmarks/skill_bench/src/skill_bench/failure_evidence.py) reads a closed bounded host CLI stream and exposes allowlisted event counts, hashes and failure categories. Client exit or timeout takes precedence over missing completion usage. An explicit `failed-turn-v1` review condition withholds inherited workspace images only when the supported stream verifies that no model-output event was observed; malformed, absent or unfamiliar streams remain unknown. Partial output retains its limited scope. Persisted files and original result seals are preserved, and old review/export defaults retain their original semantics.

## Alternatives considered

- Generic start/middle/end stills cannot resolve requested interaction or audio conditions.
- Trusting solver-authored observations or captions would reward unsupported assertions.
- Inline private images in public reports would change publication permissions and duplicate reference bytes.
- Retrofitting new conditions or binary human answers into historical ratings would obscure changes in what was measured.

## Consequences

New runtime and review conditions form separate cohorts. Sampled evidence does not establish full continuity, an application's internal FFT or a general aesthetic gain. The [evaluation protocol](../../../../../../docs/research/art-skill-diversity-2026-10-13/evaluation-plan.md) preserves source-session clustering, a bounded manual launch ledger and unused holdouts. Skill changes require repeated actionable evidence and a paired test; screening alone is not an adoption claim.

CLI reconnect attempts are provider transport behavior, not extra benchmark turn launches. The manual ledger bounds user-turn launches; provider request counts are unknown. Explicit new experiments after a verified runtime repair have separate plans, result directories and evidence identities, and do not rewrite a failed or interrupted reservation.

Long manual batches use finite one-shot user services, with no recurring timers, startup registration or CI generation. The service context passes the same zero-model backend doctor before generation. A dead launcher without terminal CLI completion cannot be reconstructed as a successful turn: preserve completed sealed rows, capture the surviving partial workspace under the existing ceilings, bind its closed stream hash, append an interrupted result and keep duration/usage unknown. New complete episodes remain explicit plans within the shared budget. The preview is a separate finite local service serving only validated report assets.

The [screening results](../../../../../../docs/research/art-skill-diversity-2026-10-13/screening-results.json) separate original-session coverage from related garment diagnostics. The [paired hypothesis](../../../../../../docs/research/art-skill-diversity-2026-10-13/refinement-hypothesis.json) changes one fashion-reference sentence, with counterbalanced arm order and a predeclared adoption gate. The [decision](../../../../../../docs/research/art-skill-diversity-2026-10-13/refinement-decision.json) retains the baseline: native evidence favors the candidate, while the static pair lacks comparable later baseline turns. A prior diagnostic episode cannot replace that missing formal control. Resource-read command references are bounded process observations, not comprehension or causal-use proof.

The [symbol calibration](../../../../../../docs/research/art-skill-diversity-2026-10-13/symbol-human-calibration.json) adds two actual human Yes answers to the independently retained garment and card sidecars. Earlier or intervening report exposure is unknown; the record is not blind gold data and does not rewrite ordinal ratings. Final execution metadata preserves unknown provider request counts and the missing terminal turn record.
