# Original-session development expansion

The [current metadata catalog](catalog.json) indexes nine local-private task definitions derived from 27 actual user messages in two source sessions. They use 29 distinct exact original attachments, including sketches, interface screenshots, a six-image reference set and a separate three-image narrative-art set. No original attachment bytes are committed here. Bounded manual screening uses the retained skill; execution and independent review coverage are recorded in local research archives.

The previous public trajectory tasks use labeled replacement diagrams. This release uses original attachments and separately scoped component studies; it is a different input condition. It does not package the original website state or claim faithful application replay. All tasks are development data. Episodes from one session are correlated, and source material already inspected during skill development cannot support an unseen-task claim.

| Task | Main relationship | Backend group |
|---|---|---|
| Card contour, proportion and text flow | Cover-height fit, top alignment and contour-aware text placement | Static SVG |
| Multi-reference analysis with corrected target | Correct the inferred glow target while retaining the actual references | Browser |
| Perspective spacing and wave variation | Near/far interval growth, nonuniform wave timing and retained depth | Browser |
| Audio-linked curves and graceful fallback | Cover ownership, controlled audio response and unavailable-analysis fallback | Browser |

| Irregular material marks with recognizable meaning | Material identity and compact Blog/GitHub destination recognition | Static SVG |
| Three-image narrative-art analysis | Actual-image annotation, grounded differences and accessible explanation | Static SVG |

Each local case uses the existing version-2 task schema, exact asset hashes, prompt-linked requirements, activation turns and scoped evidence. Alternate-solution requirements stop after the relevant exploration stage; rejected-ray requirements stop when the user changes direction. Fixed artifacts, neutral study context, deterministic controls and observation records are benchmark additions, not new historical user acceptance.

The current private suite release is version 4. The [version-1 catalog](catalog-v1.json), [version-2 catalog](catalog-v2.json) and [version-3 catalog](catalog-v3.json) are retained. Version 2 provides a bounded 64 MiB output workspace for the three large image annotations; other tasks retain 32 MiB. Version 3 adds explicit inspection controls and evaluator-owned action/audio plans to the six browser tasks. Version 4 revises only audio-ring, cover-transition and diagonal-track inspection contracts: independent geometry traces, actual media pause/resume, repeated link/player clicks, explicit inherited label travel and a distinction between targeted authoring checks and full evaluator replay. These are new task conditions, not retroactive corrections or historical user acceptance. Static cases, original attachments and earlier suite bytes remain unchanged.

Three static cases have no new evidence-capability requirement. Six browser cases require `action_trace_capture`; audio-ring and cover-transition also require `web_audio_probe`. The trusted driver implements these separately gated evaluator capabilities. A case-contract pass does not remove the runtime acceptance gates. The backend must not silently substitute sparse screenshots or a solver-authored observation file for independently reproduced actions and conditions. Every fresh run records actual doctor results and exact runtime identities.
